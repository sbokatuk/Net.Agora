## What's changed

**Chat debuts**: `Net.Agora.Chat` / `.Maui` **1.4.0.1** — one awaitable API over Agora Chat (IM
1.4.0) on Android and iOS. Sign in and out, send text messages, receive them through a
`MessageReceived` event, read the local conversation list, rotate the token, and be told when the
service ends the session and why.

```csharp
var chat = new AgoraChatOptions
{
    AppId = "your-app-id",
    UserId = "alice",
    Token = "chat-token-from-your-server",   // required — Chat has no App ID-only mode
}.CreateClient();

chat.MessageReceived += (_, e) => Show($"{e.Message.From}: {e.Message.Text}");

await chat.LoginAsync();
await chat.SendTextMessageAsync("bob", "hi");
```

Unlike Signaling, Chat does get a MAUI companion: Android's `ChatClient.Init` takes a `Context`,
so `Net.Agora.Chat.Maui`'s `CreateClient()` is what keeps an app free of `#if ANDROID`. The two
SDKs hide a real difference behind it — Android reports a send through a callback attached to the
message, iOS through a block on the send call — which the on-device suite exercises directly.

**The RTC feature extensions ship.** Twelve new package pairs
(`Net.Agora.Extensions.<Name>.Android` / `.iOS`) carry the native payloads Agora publishes
separately from the RTC SDK: AI noise suppression, AI echo cancellation, audio beautification,
spatial audio, virtual background, content inspection, video enhancement, face capture, face
detection, video quality analysis, and the software H.264/AV1 encoders. They depend on neither RTC
package — the Video and Voice bindings are mutually exclusive, and the audio extensions work with
both — so an app adds only what it turns on.

`Net.Agora.Video` and `Net.Agora.Voice` grew the switches that drive them:

```csharp
client.SetNoiseSuppression(AgoraNoiseSuppression.Aggressive);   // + Net.Agora.Extensions.Ains.*
client.SetVirtualBackground(AgoraVirtualBackground.Blurred());  // + ...VirtualBackground.*
client.SetVideoDenoiser(true);                                  // + ...ClearVision.*
```

These are the one place in the façades where a native return code is not swallowed: without the
extension's payload the call compiles, links and then fails, so a refusal raises an
`AgoraVideoException` / `AgoraVoiceException` naming the package to add. Spatial audio, content
inspection and face capture have packages but no façade call yet — each needs a surface of its
own; the video-quality analyser and the encoders are selected by the engine itself once present.

`Net.Agora.Video`/`.Maui` and `Net.Agora.Voice`/`.Maui` advance to **4.6.2.4** for those additions
and for the platform-pin bump to the revision-4 iOS bindings; the Android bindings are unchanged
at `4.6.3.3`.

**The Interactive Whiteboard and Fastboard debut.** `Net.Agora.Whiteboard` / `.Maui` **2.16.137.1**
is a shared drawing surface: join a room, pick a tool and colour, draw, undo, redo, clear, go
read-only. `Net.Agora.Fastboard` / `.Maui` **1.4.5.1** is the same board with netless's toolbar
already drawn and wired, for an app that wants a working whiteboard rather than a canvas to build
a UI around.

```csharp
// <agora:AgoraWhiteboardView x:Name="Board" /> in your XAML — or AgoraFastboardView
var board = Board.CreateClient(new AgoraWhiteboardOptions
{
    AppIdentifier = "your-whiteboard-app-identifier",   // not an RTC App ID
    RoomUuid = uuid,                                    // both from your own server's call
    RoomToken = token,                                  // to the whiteboard REST API
    Uid = "alice",
});

await board.JoinAsync();
board.SetTool(AgoraWhiteboardTool.Pencil, color: 0xE81123, strokeWidth: 4);
```

Both are netless's rather than Agora's own, which shows in two places a consumer will notice. The
identifiers come from somewhere else — the App Identifier from the Agora Console under Interactive
Whiteboard, the room UUID and token from your own server, because minting them needs a secret an
app must not carry. And each product's two platform packages sit on **different version lines**
(Whiteboard 2.16.123 on Android and 2.16.137 on iOS; Fastboard 1.8.1 and 1.4.5), because netless
releases the two from separate repositories.

The board is a web view on both platforms rather than a native canvas, so both MAUI packages carry
a view and its handlers, like `Net.Agora.Video.Maui` rather than the glue-only Voice and Chat ones.
For Fastboard the MAUI package earns more than that: Android hands the SDK a view the app supplies
while iOS's Fastboard creates its own, and `CreateClient()` is where that disappears.

## Tests and samples

- The unit tests cover `AgoraChatOptions` validation (including the App ID / app key
  exclusive-or), the Chat event-arg types, and `AgoraVirtualBackground`'s factory methods.
- The package tests grew a Chat product row.
- The on-device suite gained a Chat flavour (`-p:AgoraDeviceProduct=Chat`) — construct, guard
  validation, a full async round trip without credentials (sending before a sign-in is refused
  with `201` through the awaitable path on both platforms), an empty local conversation list,
  cancellation vs. timeout, sign-out/dispose hygiene — and the RTC flavours gained an extension
  check that fails when the payloads are missing, confirmed by building the same app with
  `-p:AgoraReferenceExtensions=false`.
- The on-device suite also gained Whiteboard and Fastboard flavours. Both refuse an unregistered
  room with the SDK's own message on both platforms, which is worth more than the pass: reaching
  it means the board's JavaScript loaded and its bridge answered — and on iOS, that a chain of
  Swift and Objective-C layers linked out of one static library actually resolves at runtime.
- `samples/Net.Agora.Sample.Chat` is a one-to-one MAUI chat, `samples/Net.Agora.Sample.Whiteboard`
  draws with hand-rolled controls and `samples/Net.Agora.Sample.Fastboard` the same board with its
  own toolbar; `samples/Net.Agora.Sample` grew switches for background blur, video enhancement and
  AI noise suppression.
