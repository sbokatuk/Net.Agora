## What's changed

**Signaling debuts**: `Net.Agora.Signaling` **2.2.6.1** — one awaitable API over Agora Signaling
(RTM 2.2.6) on Android and iOS: `LoginAsync`, `SubscribeAsync`/`UnsubscribeAsync`,
`PublishAsync` (each awaiting its own native completion — RTM reports per-operation, so there is
no join-style state machine), a `MessageReceived` event carrying string or binary payloads,
connection lifecycle events, and token rotation.

```csharp
var signaling = new AgoraSignalingClient(new AgoraSignalingOptions
{
    AppId = "your-app-id",
    UserId = "alice",
});

signaling.MessageReceived += (_, e) => Show($"{e.Publisher}: {e.Text}");

await signaling.LoginAsync();
await signaling.SubscribeAsync("lobby");
await signaling.PublishAsync("lobby", "hi all");
```

No MAUI companion exists because none is needed: RTM requires no Android `Context` and renders
nothing — the same package serves MAUI and plain .NET for Android / .NET for iOS apps.
Signaling coexists with either RTC product in one app; the RTC pair remain mutually exclusive
with each other.

**Releases now publish each product at its own version.** Signaling's 2.2.x line is what forces
it: no single tag version can be stamped across the products anymore, so `BuildNugets.sh` packs
each product at its own pin (`--suffix` for prereleases), a tag is just the train's label, and a
product whose pin did not move since the previous train is skipped by the push rather than
republished. `Net.Agora.Video`/`.Maui` and `Net.Agora.Voice`/`.Maui` advance to `4.6.2.3` for
that packaging change and for the platform-pin bump to the revision-3 bindings
(`Net.Agora.Video.Android`/`Voice.Android` `4.6.3.3`, `Net.Agora.Video.iOS`/`Voice.iOS`
`4.6.2.3`) — their client surface is identical to `4.6.2.2`.

## Tests and samples

- The unit tests cover `AgoraSignalingOptions` validation (App ID **and** user ID) and the new
  event-args types alongside the RTC products'.
- The package tests grew a product row with an optional MAUI column — Signaling deliberately has
  none — and still hold every façade to exact `[x.y.z]` platform pins.
- The on-device suite gained a Signaling flavour (`-p:AgoraDeviceProduct=Signaling`): construct,
  guard validation, a full async round trip without credentials (publishing before a login is
  rejected by the service with `-10025` through the awaitable path), cancellation vs. timeout on
  a failing login, logout/dispose hygiene — passing on an Android emulator and an iOS simulator.
- `samples/Net.Agora.Sample.Signaling` is a tiny MAUI chat room: log in, subscribe, publish,
  watch messages arrive.
